# 从人工样本提炼生成规则

## 开发目标与输入边界

开发链路是“教案图片 → skill 生成 PPT → 用户人工整理 → 将改进提炼回 skill”。人工整理稿提供目标效果；下一次运行仍由图片产生全新的教学内容和页面。日常使用无需再提供已有 PPT。

分析样本时，比较原图、原生成稿与人工整理稿：辨认哪些变化是知识点组织、版式、高亮、动画，哪些是后来补入的练习或解析。本 skill 只学习非题目解析部分。样本中的新知识、提示、笔误和数量差异不能取代教案原文。

## 把人工修改落实为生成能力

- 首页：提炼课→框→目→知识点/记忆线索的布局，记录各列宽度、括线、节点尺寸、字号、行距及聚合方式。单页整课脑图的要求应在生成过程中满足，不能拆成多页分目导航充数。
- 正文：提炼定义、对照表、并列依据、从属解释、过程与结论等页型；按新图片的语义关系选择页型，保持完整知识单元，不照抄某课页数或每页具体文字。
- 高亮：提炼标注依据，再从新图片原文中选择片段。样本的黄底词不能变成跨课硬编码词典。
- 动画：提炼标题先显示、知识点与解释同组、依据先于结论等节奏；针对新生成对象建立动画，不搬运样本对象 ID 或时间轴。
- 页码：不学习右下角页码角标；原文知识点编号及讲义来源标识仍分别处理。

将可复用规则落实到 references、结构化编排数据和 scripts。尺寸与字号使用同一坐标单位（例如 PPT 的16pt在96dpi坐标中约为21.3px），不能把通用26px下限套到样本上强制拆页。渲染器的固定列宽、段距或页眉导致不适配时，应修正实现，不能绕过生成流程去复制人工页面。

## 从图片重新生成与验收

生成过程是：读图并核对 → source.json → 层级/摘要/标注/分页与动画计划 → deck.json → 从空白创建原生可编辑对象 → PPTX → 独立检查。每个正文单元和脑图摘录均有图片来源；正文全量呈现，摘要不抵扣覆盖。

验证至少分别记录：图片识读准确性、正文覆盖和顺序、脑图归属与紧凑程度、与人工样本的版式差距、高亮依据、WPS显示和播放。仅修改说明文档或将现成样本复制成功，不能宣称生成能力已改善或试跑通过。

试跑从图片开始，不给生成过程喂入历史逐字稿、旧 deck.json 或可复制的样本页面作为答案。评审可读取人工稿和历史核对记录。使用明确指定的模型及强度时保留配置与结果；不把其他模型的手工补修计入该模型成绩。

个人原图和人工课件保留在评测目录；发布 skill 时只保留必要的通用规则、实现与不含私人教学内容的测试材料，不把用户成品课件打包为生成依赖。
